# Rexonance 3D build

Procedural Blender model of the Rexonance suit, built from the owner's ten-view
sheet (`design/rexonance-3d-20261030/reference/`) and shown on the site with
three.js. Everything is generated by Python: no hand-edited .blend is checked in.

## Run

```sh
# bpy 5.2 as a Python module (Python 3.13). On a fresh Linux box also install
# libegl1 libgl1 libxkbcommon0 libsm6 libxi6 libxxf86vm1 libxfixes3 libxrender1.
python -m venv .bpy && .bpy/bin/pip install bpy==5.2.3 pillow scipy scikit-image
.bpy/bin/python scripts/blender/rexonance3d/build.py --parts all \
  --render front,right,back,left,persp --out output/rexonance-3d/build
```

`build.py --help` lists the options. The most useful ones:

| option | effect |
| --- | --- |
| `--parts helmet,tail` / `--parts all` | armour modules to add on top of the body |
| `--render front,right,back,left` | orthographic renders that overlay the reference sheet pixel for pixel, plus `cmp-<view>.png` = [reference \| render \| 50 % overlay] |
| `--render persp` | four 3/4 perspective views and `persp-sheet.png` |
| `--zoom "front:0,1.76,0.42;right:0,1.76,0.42"` | close-ups: a size x size metre window centred on view coordinates (h, z); writes `zoom-N.png` and `cmpzoom-N.png` [reference crop \| render \| overlay] |
| `--engine cycles` | material preview (glossy black, metallic gold, emissive crystal); slower than the default Workbench form review |
| `--release` | joined web export `rexonance-raw-release.glb` + `model-manifest.raw.json`, then `pack_release.mjs` |

The undersuit is cached in `output/rexonance-3d/cache/` (keyed by the source of
`rx_body.py` and `rx_ref.py`). Output folders are git-ignored.

`refcrop.py` cuts a labelled-grid crop out of any sheet for reading positions:
`python refcrop.py front 380 0 640 300 out.png --scale 3 --grid 20`.

## Frame and reference mapping (`rx_ref.py`)

* metres; Blender +Z up; the suit faces **-Y**; the suit's own **left hand is +X**.
  (glTF: +Y up, faces +Z, left hand +X.)
* one scale for every sheet: `S = 2.0 m / 1510 px` (crown tip 2.00 m, sole 0).
* `rx_ref.px(view, x, y) -> (h, z)` converts a sheet pixel to world metres;
  `h` is X for `front`/`back` and Y for `right`/`left`.
  `front` = `front-10.webp`, `back` = `back-09.webp`, `right` = `right-07.webp`
  (camera on the suit's right, the suit faces image-right), `left` = `left-08.webp`.
* The sheet is a painting: front-10 decides widths and heights, right-07 decides
  depth; the others are for reading details. Views disagree by a few cm.
* `rx_ref.LM` holds landmarks (shoulder, elbow, wrist, fist, hip, knee, ankle,
  belt and chest-core heights...) for the suit's left side; mirror X for the right.

## Conventions every part follows

1. One module per part: `part_<name>.py` with `build(ctx)`. `ctx.body` (rx_lib.Body:
   `hit(view, h, z)`, `closest(p)`, `ray(o, d)`), `ctx.coll("<name>")`,
   `ctx.LM`, `ctx.lib` (= rx_lib), `ctx.ref` (= rx_ref).
2. Build meshes **in world coordinates with identity object transforms**.
3. Names: `RX_<Part>_<Piece>` and `_L` / `_R` for sided pieces. Author sided
   pieces on +X (`_L`, the suit's left) and copy with `rx_lib.mirror_x()`;
   only genuinely asymmetric pieces (the tail) skip mirroring.
4. **One material per object**, only from `rx_lib.material(family)`:

   | family | use | runtime look |
   | --- | --- | --- |
   | `Suit` | the scaled undersuit and scaled armour panels | near-black, small overlapping scales (triplanar normal map), clear coat |
   | `Black` | smooth lacquer shells: helmet, gauntlets, shin guards, boot shells, tail segments | mirror-gloss black |
   | `Gold` | trims, rims, horns, rings, pendants | polished bronze-gold |
   | `GoldDark` | recessed inner frames, back faces of gold parts | deep bronze |
   | `Silver` | the few white-metal chevrons (below the knee guards) | polished silver |
   | `Crystal` | holographic fins, blades, ribbons, inlays, belt cells | blue -> violet -> pink glow with a facet network and sparkles |
   | `Gem` | faceted star jewels (medallions, belt, thigh, knee, foot) | bright faceted jewel + star glint |
   | `Glow` | chest-core orb, buckle orb | white-blue emissive core |
   | `Visor` | the V eye lines and face light | pink/blue emissive |
   | `Dark` | gaps, undersides, inner recesses | matte black |

5. **Crystal UVs**: v = 0 at the root (attachment) and v = 1 at the free tip;
   u runs across. The runtime gradient is blue at the root, violet, pink at the
   tip, with pink edges. `prism()`/`band()` map UV from local (x, y), so author
   2D outlines with the tip toward +y, or pass `uv_bounds`. `sweep()`/`tube()`
   give v along the path. `rx_lib.tint(ob, pink, sparkle, edge)` biases a piece
   (pink = 0 keeps the gradient, 1 is pink throughout).
6. Star glints: put `rx_lib.glint(name, location, size, coll, hue)` at the
   centre of every star jewel; the viewer draws a twinkling four-point star there.
7. Gold and black hard-surface pieces get small bevels (1-3 mm) so they catch
   highlights; `smooth(ob, angle)` keeps hard edges above `angle` degrees.
8. Animated pieces: keep them as separate nodes. Pivots are **empties** with
   the meshes as leaf children (the release join leaves parented objects and
   anything with `ob["rx_keep"] = 1` alone; everything else is joined per part
   and material).
9. Budget (triangles): body 150k (fixed), helmet 60k, torso 70k, shoulders 110k
   (both), waist+ribbons 100k, arms 90k (both), legs+boots 110k (both), tail 50k.
10. Do not edit the shared files (`rx_*.py`, `build.py`, `export.py`,
    `pack_release.mjs`). Work around problems in your own module and report them.

## Toolkit (`rx_lib.py`)

* curves: `catmull_rom(points, samples)`, `resample(points, n)`, `rmf(points, up)`
* profiles: `circle_profile`, `superellipse_profile`, `lens_profile` (blade
  section), `rounded_rect_profile`
* sweeps: `sweep(path, profile, scale=f(t)->(sx, sy), twist=f(t), normals=[...])`,
  `tube(path, radius)`
* 2D -> 3D: `blade_outline(spine, width_fn)`, `offset_outline(outline, d)`,
  `prism(outline, depth, bevel, matrix)`, `band(outline, width, depth)` (rims),
  `ring(r_out, r_in, depth, seg, round_edge, matrix)`, `disc(r, depth, dome=...)`
* gems: `gem_kite(w, h, depth)`, `gem_round(r, depth, n)`
* placement: `frame(origin, x_axis, y_axis)`, `frame_from_normal(origin, normal, up)`,
  `transform(bm, matrix)`
* on the body: `Body.hit(view, h, z, start=None)` (`start` begins side rays inside the arms),
  `conform_plate(body, view, outline_hz, thickness, gap)` (a shell
  plate whose footprint is drawn in a view and laid on the body),
  `conform_strip(body, view, path_hz, width, thickness, gap, width_fn)` (raised
  trim along a path drawn in a view), `surface_point(body, view, h, z, lift)`
* objects: `from_bmesh(bm, name, coll, family, angle)`, `from_arrays`, `mirror_x`,
  `join`, `tint`, `glint`, `smooth`, `collection`

Example:

```python
import rx_lib as L, rx_ref as R

def build(ctx):
    coll = ctx.coll("legs")
    cx, cz = R.front(617, 810)                      # thigh diamond centre, suit's left
    outline = [(cx, cz + 0.10), (cx - 0.045, cz), (cx, cz - 0.10), (cx + 0.045, cz)]
    plate = L.conform_plate(ctx.body, "front", outline, thickness=0.010, gap=0.004)
    gem = L.from_bmesh(plate, "RX_Legs_ThighDiamond_L", coll, "Crystal")
    L.tint(gem, pink=0.4)
    L.mirror_x(gem)
```

## Release

```sh
.bpy/bin/python scripts/blender/rexonance3d/build.py --parts all --release --out output/rexonance-3d/release
RX_GLTF_DEPS=/path/to/node_modules node scripts/blender/rexonance3d/pack_release.mjs \
  --input output/rexonance-3d/release/rexonance-raw-release.glb \
  --output public/rexonance-3d-20261030/rexonance.glb
```

`RX_GLTF_DEPS` is a separate folder with `@gltf-transform/core`, `extensions`,
`functions` 4.x and `meshoptimizer` installed (the site's dependencies stay as
they are). three.js loads the result with `MeshoptDecoder`.
