# 遷移直後のスクロール修正（2026-09-21）

## 原因と修正

オープニングから `/world` に遷移する際、遷移先の描画完了後も到着演出が終わるまで `data-loading` による文書固定と、全面の handoff レイヤーによる入力遮断が残っていた。修正前の公開用ビルドで、新しい回帰テストが `arrival must release the document loading lock` の失敗を検出することを確認した。

到着フェーズ開始時に文書固定を解除し、到着レイヤーを入力透過にした。遷移前のカバー中は従来どおり入力を保護し、視覚演出・エラー時の解除処理は維持する。選択スライダーへの接触中の固定、長押し拡大、横操作は変更していない。

## 検証

- `env -u DATABASE_URL APPLY_DESTRUCTIVE_MIGRATIONS=0 npm run release:build`：lint（既存警告11件、エラー0件）、384テスト、型検査、ビルドが成功。DBマイグレーションは未設定のためスキップ。
- `node scripts/sync-source-parts.mjs --check`：15グループ一致。
- `verify-opening-arriving-scroll.mjs`：390×844・1024×768の通常演出、390×844・1280×960のモーション軽減で検証。Chromiumでは到着レイヤーが存在する間に指操作を開始し、文書のスクロールを確認。WebKitでも入力透過とホイールスクロールを確認。
- `verify-modal-scroll.mjs`：390×844・1280×800でメニュー、告知、Dreamモーダルと閉じた後のスクロール復帰を確認。
- `verify-hero-touch.mjs`：390×844・1024×768・1280×960のトップの見出し、本文、画像、ボタン、余白を検証。8人のライダーの枠寸法、長押し拡大、接触中の固定と解除、画面回転後の復帰も検証。
- Liquid rail の単体テストに、指を離す、キャンセル、キャプチャ喪失、フォーカス喪失、ページ離脱、非表示化、回転、横幅変更の8つの解除経路を追加。

補足のChromium指操作監査では、iPhone・横向きiPad相当のEPカード、EP横カルーセル上の縦スワイプ、Dream画像、Dreamモーダルの見出し・本文で約191〜222pxの縦移動を確認。iPhoneのコラムラベル上の移動も確認した。iPadのコラムラベルのサンプルはヒット位置が別セクションだったため結果から除外した。

これらはブラウザーによる画面サイズ・タッチ入力検証であり、実機iOS Safariの試験ではない。公開経路は従来どおりGitHub mainへの反映のみとし、Grok側の公開操作やSitesの新規公開は行わない。
