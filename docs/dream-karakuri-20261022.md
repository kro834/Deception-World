# Dream Chapter — からくりの劇場案内

六章の札を引くと障子が開く「からくり章案内」、台詞と章の言葉を手動で繰り出す「ことばの巻取箱」、舞台の灯りを切り替える「夢灯り」を追加した。既存の日本語本文・イラスト・章番号を使用し、新しい設定や物語は追加していない。木枠、組子、生成りの紙、真鍮の軸を共通の意匠とし、本文へのリンクは通常のフラグメントリンクのまま残している。

## 操作と負荷

章案内は矢印キー・Home・Endに対応する。選択していない紙面は `inert` と `aria-hidden` で操作対象から外し、六面のグリッドを重ねることで切り替え時の高さを保つ。読書室入口と各章への直接リンクもある。巻取箱は連続操作でも現在値を基準に更新し、名台詞と章の言葉それぞれの位置を保持する。自動送り、常時動く背景、タイマーでのループ、新しい画像やライブラリーの読み込みは追加していない。

障子と紙送りは操作時だけ有限時間で動く。reduced-motion、低負荷表示、動作無効設定では演出を止め、文字やリンクを隠さない。小さなラベルは12px以上とし、紙面のフォーカス枠は暗色、操作対象は44px以上を基本とする。追加したCSSはDreamルートだけに読み込み、既存のZenithシートの後、cinematicシートの前で適用する。

## 検証で修正した既存のWebKit不具合

画面回転後に現在の `#cases` を再度押すと、WebKitが直前の幅のレイアウトを使って大きく手前に止まる。変更前の `ac87c4b9` でも同じ失敗を再現した。`holdFragmentPath` で経路を実体化してから同じフラグメントへの明示的スクロールを1フレーム待つようにした。新しいフラグメントの通常移動、履歴、フォーカス、同時に保持される検索経路は変更していない。新しい操作やアンマウント時には予約を取り消し、実行直前にも現在のハッシュを再確認する。

## 確認方法と証拠

静的ゲートは `npm test`、`npm run typecheck`、`npm run lint`、`node scripts/sync-source-parts.mjs --check` と `DATABASE_URL= npm run build`。外部DBのマイグレーションは実行していない。

`scripts/verify-dream-karakuri.mjs` はChrome／WebKitで320×640、390×844、768×1024、1024×768、1440×900を確認し、390幅の通常アニメーション、reduced-motion、低負荷設定も確認する。章の選択、非選択面の操作不可、切り替え時の高さ、本文への移動、巻取箱の前後操作、灯りを変えても本文が残ること、紙面リンクの実際のキーボードフォーカスと色、横方向のはみ出し、未捕捉JavaScript例外を検査する。画面記録は `output/playwright/dream-karakuri/{chrome,webkit}/` に出力する。

既存の `verify-dream-reader-navigation.mjs` は320・390・1440幅と横長画面で章リンク・関連記録・キーボード・履歴を確認する。`ENFORCE=1` の `verify-dream-scroll-work.mjs` は縦横切り替え後の着地、仮の `content-visibility` 保持の解放、スクロール中の全体再描画とスタイル参照の予算を確認する。

作業中にはDNS障害があり、外部フォントとGrok編集拡張が検証を待たせたため、明示的な `PW_OFFLINE_EXTERNALS=1` を検証スクリプトに追加した。このモードはGoogle Fontsと当該編集拡張の正確なURLだけを遮断し、通常実行の挙動や検査内容は変えない。回線復旧後は遮断しない通常条件でも再検証する。WebKitのリンク巡回にはmacOSのOption+Tabを用い、動的な `inert` と可視状態が描画へ反映されてからフォーカスを検証する。

iPhone／iPad実機の検証を行ったという主張はしない。ブラウザーのタッチ・画面サイズ再現と実機のホーム画面起動は別の確認範囲である。公開の成否はGitへの反映だけでは判断せず、本番のリリース識別と配信チェックで確認する。
