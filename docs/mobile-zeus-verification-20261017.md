# スマホのゼウスボタンと検証整合性（2026-10-17）

スマホの縦・横画面では、スクロール中のみゼウスボタンを非表示にし、最後のスクロールから180ms後に再表示する。位置設定の保存内容、長押しドラッグ、キーボードフォーカス中と遷移中の操作は保つ。画面復帰・リサイズ・破棄時に非表示用タイマーを解除する。タブレット通常幅の表示は変更しない。

## 検証スクリプト

`verify-column-frame` は899px以下の3列・2行レールの36px角丸を反映し、6タブすべてのタップと同じ行の長押しドラッグを確認する。`verify-world-programme` は各details直下のsummaryを選び、入れ子のsummaryと衝突しないようにする。段落数・本文は書き換えず、既存の `DREAM_CASES` 全文・順序照合を維持する。

`verify-rising-world` の生存ビットマップ確認は、Rising所有の576×768・683×1024に限定する。レクソナンスの先読みに属する別サイズはRisingの解放失敗には数えない。所有する2点の準備・破棄・往復再準備の条件は維持する。

`verify-route-transitions` のdesktop world-zeus 250msは、実画像では中央の紋章が見えるものの、全画面の平均輝度0.00333・標準偏差0.01199・99.5パーセンタイル0.03080が既存の暗転判定に該当していた。ゼウスの中央領域のディテールを追加確認し、均一な暗転や単一の光点だけは依然失敗とする。ほかの遷移・点滅・時間予算の条件は変えない。

## 実機確認とCPU4倍の未完了条件

ローカルの実ブラウザでは、Chrome／WebKit各320×740・390×844・844×390・1024×768でスクロール非表示・停止後復帰・位置保存不変・低減モーション・キーボードフォーカス維持が合格。Chromeのゼウス長押し・中断・保存位置の復帰は390×844・1024×768で合格。レールの縦スクロール・短いタップ・長押し・2次元プレビュー・単一コミット・マルチタッチ中断・キーボード・寸法不変は320・390・768pxで合格。WebKitのphone-390入場コール・最新ステージ優先・中断後片付けも合格。これらは実機の代替とはしない。

修正した検証は、コラム8幅（320・360・375・393・412・430・768・1376px）、World／Dream4幅（390・375・1024・1194px）、PixelのRising tiers、desktop world-zeusで合格。world-zeusの点滅は一般・赤とも0、空白0、カバー消去967ms。Rising画像は接近時2枚→離脱後0枚→復帰後2枚を強制GC下で確認した。

接続可能な操作環境にiPhone／iPad実機はなく、オーナーが実機で確認して結果を送る予定。WebKitの画面寸法エミュレーションを実機Safariの合格とは扱わない。Chromeが最小化後も `document.hidden=false` を返す場合、背景化の結果は既存どおり `unverified` とする。可視性を偽装して実背景化の合格にはしない。

CPU4倍のPixel 412×915・DPR2.625・遅延60ms／下り9Mbps／上り1.5Mbpsで `first-visible-native-menu-1000` を再計測した。初回のSSRヒーロー観測は1927.2ms、目標2927.2ms、実入力5236.4msで、SSR観測から3309.2ms、目標から2309.2ms遅れた。初回のボタン境界が取得できず、配置確定を待ってから入力したため、1秒以内の入力確認は不成立。`firstVisibleInput.earlyInputVerified=false`、`earlyInputStatus=late-and-handled`。再タップなしでメニューが開き、その後のナノマシンエンジン経路は通ったが、それを早期入力の合格とは扱わない。

他のブラウザ検証・ビルドを止めた独立再計測では、SSR観測1934.7ms、目標2934.7ms、ネイティブ入力送信は予定比−0.7ms、ページ側受信2953.7ms（SSR基準1019ms・目標比19ms遅延）。既存の許容100msの条件では `earlyInputVerified=true`、再タップなしで処理された。ただし、1000ms以下の受信を厳密に証明する結果ではなく、メニュー表示も即時ではない。表示確定後の追加待ち547msで開いた。二つの計測を混同せず、初回結果を削除しない。

この計測の基準は「カバーのないSSRヒーローDOMをrAFで観測した時点」であり、コンポジタの初描画そのものの保証ではない。厳密な初描画→1秒以内の入力を証明するには、初描画時刻と入力送信・受信時刻を別々に取り、事前に確定した操作座標から入力できる検証環境が必要。測定遅延を差し引いたり基準時刻をhydration完了へずらしたりしない。

## オーナー実機チェック

機種・iOS／iPadOS版・Safari通常タブかホーム画面アプリかを記録する。レクソナンスのZENITHを往復スクロールし、途中で止めたり逆方向へ戻しても装着が飛ばないか確認する。Worldからの入場コール、戻る・再入場、レールの短いタップ・長押し選択・指を離した後の縦スクロールを確認する。入場待ち・コール中・装着途中のそれぞれでホーム画面へ戻り、復帰後に古い演出やスクロールロックが残らないか確認する。不具合は開始前から復帰後までの画面収録と再現手順を残す。
