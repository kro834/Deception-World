and did not open the menu. Its actual pointer arrived 2251 ms after the first SSR
hero observation, despite the requested 1000 ms deadline. A ~968 ms initial
bootstrap task spanned that deadline. The subsequent UI-ready retry opened the
menu and ran the real Canvas engine; that is not an early-input success.

A second host-timer attempt stopped safely because the SSR-observed menu button
did not yet have a visible bounding box. It is retained as failed/unknown evidence,
not promoted to an engine pass. The verifier now separates input submission,
actual delivery, UI readiness, and later engine success, and caches the animation
meter instead of flushing pending style/layout on every sampled frame.

Added an appearance-preserving hydration input handoff for this defect: a small
head capture retains one trusted, valid SSR menu click and prevents React from
replaying the same click. The mounted trigger claims it and delivers it after the
menu's passive input listener exists. StrictMode cancellation, normal-click
priority, route/hash changes, disconnected/disabled/inert controls, and hidden
pages are checked before delivery. Initial capture listeners are removed on claim;
there are no added timers, resource loads, storage entries, or layout reads.
